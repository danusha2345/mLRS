# Generic ELRS 900 RX как тестовый mLRS-передатчик

Этот пример позволяет собрать двусторонний mLRS-линк из двух одинаковых
миниатюрных ELRS-приёмников диапазона 868/915 MHz: один работает обычным
приёмником, второй — передатчиком. Это экспериментальный вариант для стендов и
проектов, которым подходят ограничения SX1276; он не заменяет полноценный
передающий модуль с усилителем мощности.

## Проверенное оборудование

Пример проверен на двух модулях с ESP8285N08 (1 MiB flash, 26 MHz) и SX1276 без
внешнего PA. Он подходит только платам с pinout стандартного target
`rx-generic-900`:

| Сигнал | GPIO |
|---|---:|
| SX1276 NSS | 15 |
| SX1276 RESET | 2 |
| SX1276 DIO0 | 4 |
| BOOT / bind button | 0 |
| LED | 16 |

Если модуль имеет PA/LNA, RF switch или другой pinout, этот target использовать
нельзя без отдельного HAL. Перед подачей питания подключите антенну. UART имеет
уровни 3.3 V; соедините общий GND и перекрестите TX/RX USB-UART адаптера и
модуля. Допустимое напряжение питания нужно проверять по конкретной плате.

## Сборка

```bash
pio run -e tx-generic-900-rx-as-tx -e rx-generic-900
```

Артефакты:

- `.pio/build/tx-generic-900-rx-as-tx/firmware.bin` — модуль-передатчик;
- `.pio/build/rx-generic-900/firmware.bin` — модуль-приёмник.

SX1276 работает в совместимом режиме `19Hz7x`. По умолчанию выбран диапазон
868 MHz. Для варианта `rx-as-tx` доступны 0, 10 и 17 dBm; значение по умолчанию
— 10 dBm. Это программная мощность SX1276 без учёта потерь и возможного
внешнего RF-тракта.

## Прошивка ESP8285

Переведите только прошиваемый модуль в ROM bootloader: удерживайте GPIO0 на GND
во время подачи питания. Пример для `esptool`:

```bash
esptool --chip esp8266 --port /dev/ttyUSB0 --baud 460800 \
  --before no-reset --after no-reset write-flash 0x0 \
  .pio/build/tx-generic-900-rx-as-tx/firmware.bin
```

После проверки hash отключите GPIO0 от GND и перезапустите питание. Аналогично
запишите RX-образ во второй модуль. Не стирайте flash без необходимости: это
удалит сохранённые настройки и bind.

## Bind и UART

На уже работающем устройстве удержание кнопки GPIO0 дольше 4 секунд включает
bind mode; не удерживайте её во время включения, иначе ESP8285 снова войдёт в
ROM bootloader. Переведите в bind сначала одно устройство, затем второе. При
успешном соединении штатный single LED обоих модулей горит постоянно. Светодиоды
USB-UART адаптеров показывают только локальный UART traffic и не являются
индикатором RF-линка.

UART по умолчанию:

- TX target: 115200 baud;
- RX target: 57600 baud.

Bind сохраняется во flash и после обычного отключения питания восстанавливается
автоматически.

Во время bind RX автоматически получает и сохраняет общие параметры пары:
`Bind Phrase`, `RF Band`, `Mode` и `RF Ortho`. После установления связи TX читает
настройки RX; параметры с префиксом `Rx` можно менять через TX и передавать
приёмнику с сохранением через `PSTORE`. Это не полное клонирование настроек:
`Tx Power` и `Rx Power`, а также UART port/baud каждой стороны остаются
индивидуальными.

### CLI на общем UART

У ESP8285 только один доступный full-duplex UART, поэтому data transport и CLI
не могут работать на нём одновременно. При каждом запуске TX target мигает LED
5 секунд — это окно выбора режима:

1. Подайте питание, не удерживая GPIO0, иначе включится ROM bootloader.
2. После начала мигания LED удерживайте кнопку GPIO0 не менее 250 мс.
3. UART перейдёт в режим CLI на 115200 baud. Команды `help`, `pl` и `pstore`
   позволяют просматривать, менять и сохранять параметры TX и связанного RX.
4. Команда `exit` переключает UART обратно в data transport, возвращает
   сохранённую TX baudrate и перезапускает serial parsers без перезагрузки.
   Обратный поток TX -> RX может появиться примерно через 6 секунд.

Без входа в CLI параметры также доступны online через MAVLink component
(`PARAM_REQUEST_LIST`, `PARAM_REQUEST_READ`, `PARAM_SET`). Компонент включён по
умолчанию на system id 51, component id 68. Для сохранения и передачи изменённых
RX-параметров используйте параметр `PSTORE`. RX настраивается через связанный TX;
отдельного CLI на UART приёмника нет.

## Результат аппаратной проверки

На расстоянии около 1 м после холодного старта получены следующие результаты:

- диапазон `868M`, режим `19Hz7x`, частота кадров 19 Hz;
- LQ 100% в обоих направлениях;
- RSSI примерно от -49 до -54 dBm;
- 227 native `MLRS_RADIO_LINK_STATS` кадров за 12 секунд (18.92 Hz);
- 32 из 32 уникальных MAVLink frames прошли TX UART -> RF -> RX UART;
- 32 из 32 уникальных MAVLink frames прошли RX UART -> RF -> TX UART;
- `PARAM_REQUEST_LIST` через UART TX вернул все 49 параметров MAVLink-компонента,
  включая параметры связанного RX;
- вход в CLI нажатием во время 5-секундного окна подтверждён на модуле: команды
  `help`, `pl rx` и поток `stats` работают, RF-линк при этом остаётся активным;
- команда `exit` вернула data transport без перезагрузки: RX -> TX возобновился
  через 0.047 с, TX -> RX через 5.585 с, затем прошли 49 параметров и 32/32
  уникальных MAVLink frames в обоих направлениях;
- bind восстановился после одновременного отключения и повторного включения
  обоих модулей.

Контролируемый тест валидными MAVLink frames показал:

| Направление | Предложенная нагрузка | Доставка | Наблюдение |
|---|---:|---:|---|
| TX -> RX | 800 B/s | 100% | без накопления очереди |
| TX -> RX | 1200 B/s | 100% | без накопления очереди |
| TX -> RX | 1600 B/s | 100% | с накоплением очереди; выход около 1269 B/s |
| RX -> TX | 800 B/s | 100% | без накопления очереди |
| RX -> TX | 1200 B/s | 100% | без накопления очереди |
| RX -> TX | 1600 B/s | 100% | без наблюдаемого накопления очереди |

Это UART goodput тестового потока, а не raw bitrate LoRa. Live link information
для `19Hz7x` сообщал расчётные serial data rates 1207 B/s TX -> RX и 1547 B/s
RX -> TX.

Результат подтверждает этот конкретный ESP8285/SX1276 pinout и не гарантирует
совместимость внешне похожих ELRS-плат.
